A company that survives losing anyone

I built a documentation operating system for a regulated company: one master doc per area, one doc per process, and an AI "judge" that audits them. Every doc has to pass the truck test: if the person who runs this disappeared tomorrow, could someone else take it over?

Why it mattered

Knowledge that lives in heads leaves with them

Single points of failure

In a small company, most processes are run by one person who learned them by doing. Vacations, resignations and sick days turn into outages.

AI needs written processes

An assistant can only run a process it can read: what triggers it, where the data lives, which tools it needs, who approves. "Ask Jack" isn't an instruction.

Docs rot

Documentation is right the day it's written and quietly wrong a month later. Without something that checks it, nobody trusts it, and nobody updates it.

  1. Docs describe, systems store.

    No records in the docs. Each one points to the system where the real data lives.

  2. Every doc passes the truck test.

    A mandatory continuity section: why it matters, what breaks without it, who else could run it, what's still only in someone's head.

  3. Owners edit their area; everyone reads everything.

    Folder ownership in CODEOWNERS. Leads who don't use Git ask their AI assistant, which opens the pull request for them.

  4. The judge reports, it never fixes silently.

    Seven checks run after every edit. Findings in another area go to its owner as a proposal.

  5. Decisions are written once and never rewritten.

    An append-only log, so closed debates stay closed and the "why" survives turnover.

What didn't work

The system checked itself, and found drift

Governance

Permissions on paper ≠ permissions in reality

The first time the judge compared the governance doc with the real repository, the access people actually had didn't match the roles on paper. That's now a quarterly check, not a one-time setup.

Tooling

The plan couldn't enforce ownership

The hosting plan didn't support required code-owner reviews. We kept CODEOWNERS anyway: it documents who owns what today and starts enforcing the day the plan changes. Meanwhile, ownership runs on PR discipline.

Coherence

Docs said "pending" about finished work

Several docs still described as future work things that were already live. Check B exists because of that: a Live doc that says "pending" is lying to whoever reads it next.
